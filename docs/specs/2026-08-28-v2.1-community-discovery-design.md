## 0. 为什么是现在

v2.0 验证（已冻结）：

```
AC            1.0 → 0.238
Candidate RR  ~3% → 61.9% (83/134)
PRE_2006      0% → 44.8%
```

depth 路线关闭（41 篇 CURRENT_UNRESOLVED 在 depth 1000→2000 下新增 = 0）：

```
composite     9 篇 → 0 找到
dental        2 篇 → 0 找到
photopolymer 15 篇 → 0 找到（query 仅导出 13 条，ABSENT_EXHAUSTIVE=15）
原 15 篇          → 0 找到
```

核心洞察：

> 「语义上属于某个大方向」≠「某个具体 Scopus query 能检索到它」。
> 不同 community 用不同语言描述同一现象（收缩：holographic recording /
> grating shrinkage / dimensional stability），现有 query family 穿不过社区边界。

剩余瓶颈 = **Cross-community / conceptual retrieval gap**。

## 1. 机制定位：社区发现器（Community Explorer），不是 query 生成器

v2.1 不推翻 v2.0，而是**给 v2.0 自动提供新的 concepts**：

```
v2.0:  Research Question → Concept Slots → Query Families
v2.1:  Retrieved Literature → Community Discovery → NEW Concept Slots → Query Families
```

PROMOTED community → Concept Slot Extractor 重新映射 P/M/R/C →
现有 `variant_generator / query_family / family_registry / family_scheduler`。

> ⚠️ 不是手写 "holography"/"nanoimprint" 塞进 query——那是用 QGS 答案补洞（leakage）。

---

## 2. 闭环

```
当前 Candidate DB / Relevant papers
        ↓
Community Explorer
        ↓
三个独立信号找「邻接社区」
        ├─ Citation Bridge（主信号）
        ├─ Term Co-occurrence
        └─ Review Bridge（MVP 只作额外证据）
        ↓
Community Candidates
        ↓
去重 / 聚类 / 评分 / 证据审计
        ↓
PROMOTED COMMUNITY
        ↓
自动生成新的 Query Family（复用 v2.0 pipeline）
        ↓
Scopus 搜索
        ↓
新 Candidate papers 入库
        ↓
重新做 community discovery（loop）
```

## 3. 信号定义

### 3.1 Citation Bridge（主信号：负责「从哪里跳出去」）

从当前相关论文 R 出发，对每篇获取 references（向后）+ cited_by（向前），
找「多篇独立相关论文共同指向」的结构：

```
当前社区 A
A1 ─┐
A2 ─┼→ paper X
A3 ─┘
        ↓
X 又连接一批我们从未检索到的论文
        ↓
可能存在 community B
```

Bridge strength（朴素定义，不学权重）：

```
Bridge(p) = #{ 当前 relevant papers 与 p 有 citation edge }
```

- 被 1 篇引用 → 弱
- 被 ≥8 篇相关论文共同引用 → 强 bridge candidate

理论依据：citation chasing 是系统综述中补充关键词数据库检索的标准方法
（Citationchaser, PubMed 35472127）。

### 3.2 Term Co-occurrence（负责「跳出去以后这群论文说的是什么」）

对 citation bridge 拉出的邻接论文 + 当前 Candidate DB 的
title / abstract / keywords：

```
phrase extraction → term-document matrix → term co-occurrence graph → term clusters
```

找的是：**当前 query 没覆盖、但通过文献关系与目标问题连接**的词簇。
（litsearchr 思路：term co-occurrence network → 自动生成搜索词，Grames 2019；
我们多一层：不是单纯高频词，而是「与现有 query family 低相似但结构相连」的词簇。）

### 3.3 Review Bridge（高质量社区入口，MVP 只作额外证据）

Relevant papers → 引用的 review → review bibliography 按主题分群 →
找「Candidate DB 覆盖很少但 review 中形成密集子群」的区域。

⚠️ 与 QGS 构建时的 source review 完全不同：v2.1 的 review 必须由
Agent 当前搜索**自主发现**，禁止把 QGS 那 7 篇 review 写进去。

## 4. CommunityCandidate schema

```json
{
  "community_id": "COMM_023",
  "terms": ["...", "..."],
  "citation_support": 0.71,
  "term_coherence": 0.83,
  "review_support": 0.44,
  "novelty_vs_registry": 0.92,
  "seed_papers": 17,
  "evidence": ["paper ids..."],
  "status": "CANDIDATE"
}
```

评分（MVP 固定规则，**不学习权重**）：

```
S_c = w1*C_citation + w2*C_term + w3*C_review + w4*N_registry
MVP: 固定阈值晋升（易于解释和调试）
  满足 citation_support ≥ τ_c
  AND term_coherence  ≥ τ_t
  AND novelty_vs_registry ≥ τ_n
  → CANDIDATE → PROMOTED
```

---

## 5. Novelty：与 Query Registry 比，不是与论文库比

```
Novelty(c) = 1 - max_f Sim(c, f)
  c = candidate community
  f = existing query family（query_registry_v2.json）
```

如果一个 community 的核心词是 polymerization shrinkage / volume contraction /
dimensional change → 不是新 community。只有 citation 强相连 + 术语成簇 +
与所有现有 family 低相似，才值得晋升。

---

## 6. PROMOTED → Query Family（复用 v2.0 框架）

Community Explorer 输出 community concept → **Concept Slot Extractor**
重新映射（对应现有 `concept_slots.py` 的 SLOT_NAMES）：

```
P = problem    （= slot "problem"）
M = material   （= slot "material"）
R = reaction   （= slot "reaction"  —— 机制/过程）
C = context    （= slot "context"   —— 应用/社区）
```

→ 进入现有 `variant_generator → query_family → family_registry → family_scheduler`。

## 8. MVP 范围（第一版只做两信号晋升）

```
Citation Bridge
+
Term Co-occurrence
```

- citation graph 负责「从哪里跳出去」
- term graph 负责「跳出去以后这群论文说的是什么」
- 单用 citation → 容易跑到大牛/高被引但无关社区
- 单用 term → 容易只是当前社区内部同义词
- 组合（结构相连 + 语言新簇）才是真正的跨社区

Review Bridge / 2-hop citation / temporal exploration → MVP 跑通后加。

## 9. 评估指标（冻结）

| 指标 | 定义 | 用途 |
|---|---|---|
| CDR | 晋升的新 community 数 / candidates 数 | 系统行为（不是越高越好） |
| Community Novelty | 1 - max Sim(new_comm, existing_families) | 新概念度 |
| Retrieval Expansion | 新 query 后：new unique papers / venues / year regions / citation clusters | 触达扩展 |
| MCG | |R_c − ∪R_old| | 数据库真实新增 |
| RR_QGS1 | regression / recovery metric | **只作 regression，绝不叫独立泛化** |

最终验证 v2.1 需要独立 QGS v2。

## 10. Leakage 规则（四条，冻结）

1. 禁止 QGS missed title / DOI / abstract 作为 community seed。
2. QGS-v1 告诉我们的 "holography" / "UV-NIL" 等只能作 failure-analysis 标签，
   不能进入算法输入。
3. Community 必须可追溯：
   `Agent 自己当前检索到的 paper → citation/review/text evidence → community`。
4. 若某个 term 因 QGS-v1 才知道 → `leakage=true`，且 CLEAN evaluation 排除。

已记录的 development signal（只作诊断，leakage=true）：

```json
{"signal": "COMMUNITY_ISOLATION", "community": "holography",
 "evidence": "photopolymer 组 15 篇 QGS-v1 missed：query 仅导出 13 条 (ABSENT_EXHAUSTIVE=15)"}
{"signal": "COMMUNITY_ISOLATION", "community": "UV-NIL / historical dental",
 "evidence": "12 篇 DIRECTION_GAP 含 UV-NIL 仿真、Bowen 1967、thiol-yne 边界"}
```

## 11. MVP 执行流程（10 步，冻结）

```
STEP 1   INPUT: Candidate DB + Relevant papers
STEP 2   构建 1-hop citation neighborhood
STEP 3   找 citation bridge candidates
STEP 4   对邻接论文提取 title/abstract/keywords terms
STEP 5   建立 term co-occurrence graph
STEP 6   聚类得到 community candidates
STEP 7   与现有 query_registry 比较 novelty
STEP 8   Citation support + Term coherence + Novelty → PROMOTE
STEP 9   PROMOTED → P/M/R/C slots → 现有 QueryFamily generator
STEP 10  搜索并全部写入 Candidate DB → 计算 marginal reach + QGS1 regression
```
