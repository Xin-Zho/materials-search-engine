# P4-2 v3：NODE = 知识树位置（不是规模）—— 目标改对了，但我的操作化被对照检验推翻

日期：2026-09-12 ｜ 预测器 `p4_2v2`（NODE 打分升级为 v3 口径）｜ 分析器 `p4_2_analyst_v1`

---

## 1. 用户的纠正

> 研究方向的潜力（scientific potential）和当前规模（current popularity）应该解耦。
> NODE 不该预测「哪些节点会变大」，而该预测「哪些节点处于知识空间中的**高潜力位置**」。
> `Potential(node) = f(position in knowledge tree)`，不是 `f(paper count)`。

并指出上一轮 NODE 实验失败的真正原因：我不是在找"新兴方向"，而是在找
**"大问题 / 大主题"**（`shrinkage`、`polymerization`、`mechanical property`）——
它们已经成熟，未来本来就不会突然爆发。P4-3 的数据正是这个诊断：
`challenge` 型候选 lift **0.750**，而同分层随机节点的命中率反而更高（49% vs 37%）。

这个纠正成立，且解释了已有的负结果。

## 2. 实现

### 2.1 四个结构信号 + 弱化的增长

| 特征 | 权重 | 操作化 |
|---|---|---|
| `structural_novelty` | 0.25 | 该节点的**连接有多新**（新边占比，首现 ≥2017）+ 自身首现新近度 |
| `bridge` | 0.25 | 参与系数 `P = 1 − Σ_c (k_ic/k_i)²`，模块 = 节点的**主场主题**（OpenAlex 自带分类，独立于本图） |
| `problem` | 0.25 | typed 关系指向 `challenge` 型概念，按挑战**成熟度**加权（`Σ log1p(support_c)·n`）—— 解决老瓶颈比解决新问题更值钱 |
| `combination` | 0.20 | 邻居对之间**互不相连的比例**（结构洞 / 中介度） |
| `growth_weak` | **0.05** | 用户明确「w5 → 0」，只留一个弱项 |

### 2.2 规模混淆：不是"不要规模约束"，而是"规模决定竞争组，结构决定组内排名"

第一版直接把参与系数/中介度当分数，立刻被枢纽占据 —— 实测
`photopolymerization`（deg=93）的 `P=0.91`、中介度 `0.97` 都是全榜第一：
度数一大，邻居自然横跨多个模块、邻居对自然也大多互不相连。这是**构造性**的，不是数据问题。

处理：`stratum = small(deg≤3) / mid(4–7) / large(>7)`，所有结构特征**只在层内**做百分位排名，
跨层不可比；主榜取 small+mid（用户目标正是「目前还小、但可能改变知识树结构的方向」），
large 层单列。回归测试 `test_ranking_is_within_stratum_not_across` 断言每层各有自己的 #1。

### 2.3 表征手段的标记（可评审规则）

`dynamic mechanical analysis` / `scanning electron microscopy` 这类概念的**中介度天生很高**
（每篇论文都要报告测量），按度数分层**挡不住**（实测 DMA deg=7 落在 mid 层、中介度仍 0.57）。
按词面模式标记（`NODE_METHOD_LIKE_RE`，正则写进产物供评审），排除出主榜，被排除项全部列出。

### 2.4 可测量下限（不是规模奖励）

`degree ≥ 2` 与 `support ≥ 2` 作为结构量的**可测量前提**（孤点上参与系数无定义），
被它挡掉的计数逐项记录：`node_below_min_degree 6,983` / `node_below_min_support 133`。

## 4. 但两个检验都不过 —— 而且这不是功效问题

### 4.1 结构对齐判据（伙伴广度）

用户纠正后的目标不是"变大"，所以判据也换成结构对齐的：**该概念是否在 EVAL 期获得新伙伴**
（`|eval_partners| > |train_partners|`，伙伴宇宙 = support≥3 的 429 个概念，共现 ≥2 篇算伙伴）。

| | 命中 | 中位广度增长 | 中位新伙伴占比 |
|---|---|---|---|
| 真实候选（162） | 92/162 = 56.8% | 1.021 | **0.172** |
| 同类型随机基线 | 88/162 = 54.3% | 1.066 | **0.301** |
| | lift **1.045** | z=0.447 | p=0.655 → **NULL** |

反直觉的细节：真实候选的**新伙伴占比反而低于基线**（0.172 vs 0.301）。
也就是说结构分高的节点**更嵌入**（伙伴多为老伙伴），而随机节点反而更多地拿到全新伙伴。

### 4.2 结构打分的阳性对照（决定性）

与词面尺子同样的做法：拿一组**已知在 2020 前后打开新连接**的概念，看它们在结构打分里排在哪。

```
14 个对照概念，只有 5 个在候选图内（9 个根本不在图里）
层内分数百分位中位数 = 0.42（低于中位）
其中 pet-raft polymerization 0.23 / 4d printing 0.36 / thiol-ene click chemistry 0.42
  digital light processing 0.51 / frontal photopolymerization 0.91
不在图内：vat photopolymerization / two-photon polymerization / bioprinting /
          machine learning / anisotropic shrinkage / low shrinkage / …
```

**这决定性地说明：NULL 不是（只）因为数据薄，而是我的操作化方向错了。**
若特征方向是对的，已知扩张的概念至少应该偏上，而不是中位数 0.42。

### 4.3 诊断：三个结构代理是**静态拓扑量**，等于换了个口径的成熟度

`bridge` / `combination` / `problem` 都在测量**当前已经存在的连接结构**。
一个真正的新方向在历史窗口里**恰恰是连接很少的** —— 它还没连上。
所以静态结构量必然偏向"已经是连接者"的节点，即已经成熟的节点。
这与按论文数排名的病理**同源，只是更隐蔽**。

唯一的变化型特征是 `new_edge_share`，而它在多数候选上接近 0（Top-榜里大量 0.00）——
也就是说，真正区分"正在打开连接"的信息，我在打分里只给了很小的权重，且定义过粗。

### 4.4 两个问题同时存在，且可分离

| 问题 | 证据 | 修法 | 成本 |
|---|---|---|---|
| **操作化错**（主因） | 阳性对照中位数 0.42（低于中位） | 结构特征改为**变化型**：节点在 TRAIN 内部的**伙伴获取速率**（≤2017 的伙伴集 vs 2018-2020 的新增），而不是静态拓扑 | 0（改代码） |
| **覆盖不足** | 9/14 对照概念不在候选图内 | 抽取扩到全部 5,545 篇 TRAIN | ~$10 |

## 5. 结论（要点）

1. **目标改对了**：把 NODE 从"规模"解耦到"结构位置"是对的，候选面也确实从"最大的问题"
   变成了"机制/位置"型候选。
2. **我的操作化被自己的阳性对照推翻**：三个结构代理是静态拓扑量，等价于换口径的成熟度度量；
   阳性对照落在中位数以下（0.42）是最直接的证据。
3. **因此"结构位置能不能预测未来"这个问题，本轮仍未得到检验** —— 检验的是我的一个失败代理。
   不能把它读成"结构位置无用"。要读成"这个操作化无用"。
4. **唯一通过检验的仍是边层**：PAIR lift **1.454**（z=4.10, p=4.1e-05），
   与用户自己的架构判断一致 —— PAIR 是"新关系事件"，NODE 是"新知识实体"，
   而**新事件**比**新实体**更容易从历史结构里被识别。
5. 词面尺子本身有灵敏度（阳性对照 13/13 = 100%，中位期率比 2.355），
   所以上述判断不是"仪器钝"造成的。

## 8. 追问与回答：「是知识树搭建不好，还是算法不好？」

用户 2026-09-12 追问。此前 §4 把两个问题并列写了（操作化错 / 覆盖不足）但**没有量分离**，
也**没有说清两者是耦合的**。补做两个互相独立的只读测量（`tools/diagnose_graph_measurability.py`）。

### 8.1 问题的真正形状

**A) 树：不是「搭错」，是「太浅」**

已抽取 993 篇 / in-scope TRAIN 5,520 篇 = **18.0% 采样**；每篇约 10.1 个概念。
在 7,359 的词汇表上，共现对重复出现的概率极低，于是图落在**静态拓扑量不可测**的区间：

| 采样 | papers | nodes | edges(≥2) | NODE 可打分池 |
|---|---|---|---|---|
| 25% | 248 | 2,217 | 113 | 25 |
| 50% | 496 | 4,054 | 347 | 81 |
| 75% | 744 | 5,736 | 863 | 151 |
| 100% | 993 | 7,359 | **1,323** | **243** |

幂律拟合：`edges(≥2) ∝ N^1.81`、`NODE池 ∝ N^1.64` —— **指数 > 1**。
外推至全部 5,520 篇（×5.56）：`edges(≥2) ≈ 2.98 万`、`NODE池 ≈ 4.0 千`。

**所以 243 这个候选面主要是采样深度的函数，不是算法缺陷。** 18% 采样下的
「degree ≥ 2」几乎是一次随机筛选（`anisotropic shrinkage` 出现 6 次却 0 个可测伙伴）。

**B) 算法：静态拓扑量本身没有区分度**

只把边门槛 `support>=2` 降到 `>=1`（其余全部冻结）做单变量实验，
用**同度数带**匹配（免受分层阈值在稠密图上整体失效的干扰）：

| 边门槛 | 打分池 | deg 中位 | 对照进池 | 同带百分位中位 | 排除退化带后 |
|---|---|---|---|---|---|
| `support>=2`（现状） | 243 | 4 | 5/12 | **0.286** | 0.286 |
| `support>=1`（稠密） | 429 | 40 | 8/12 | **0.594** | 0.538 |

稠密化把对照从「明显低于中位」抬到「约等于中位」，覆盖率 5/12 → 8/12。
**抬得动说明稀疏确实是一部分原因；只抬到中位说明静态拓扑量仍拿不到区分度。**
参照：词面尺子的阳性对照 13/13 = 100%、中位期率比 2.355 —— 那才叫有区分度。

### 8.2 两个问题**耦合**，不是可以排序的两个待办

- 稀疏图里能进入打分池的节点，恰恰是「已被反复共同提及」的那批，也就是**嵌入最深的**。
  这直接解释了 §4.1 的反直觉细节：真实候选的新伙伴占比 **0.172 < 基线 0.301**。
- 稠密化实验同时说明：**加粗的树是结构量可测的前提**，不是「把样本加厚」那种可选项。
  因此 §6 的「先做免费的 1+2，通过了再扩量」这个顺序**部分被本轮数据推翻** ——
  换特征仍然是免费的、仍然该做，但它与扩量是**并联**关系：在 18% 采样的图上，
  任何静态结构量都测不出方向。

### 8.3 一并修正的两个控制清单自身错误

上一轮 14 个对照概念里有两个是**我的字符串错误**（不是覆盖不足）：

| 写的 | 实际 | 后果 |
|---|---|---|
| `front photopolymerization` | `frontal photopolymerization`（同一概念重复计入） | 覆盖率被低估 |
| `photoinduced electron transfer reversible addition` | RAFT 名的截断残片，真名 8 次支撑、deg=11 且在池内 | 覆盖率被低估 |

修正后真实缺失是 **7 个不同概念**，且成因分三类（都不是「打分错了」）：
支撑度低于门槛（`two-photon polymerization` 1 次 / `low shrinkage` 1 次 /
`bioprinting` 2 次，而同义的 `3d bioprinting` 6 次在池内 —— **词形碎片化**）、
孤点被 degree 门槛挡（`anisotropic shrinkage` deg=0 / `vat photopolymerization` deg=1 /
`continuous liquid interface production` deg=1）、抽取未产出（`machine learning` 0 次）。

### 8.4 修正后的口径

1. 不能读成「结构位置无用」——本轮检验的是一个**失败的操作化**。
2. 也不能读成「只是树不够大」——稠密后对照只到中位。
3. 正确读法：**在 18% 采样的稀疏图上，静态拓扑量不可测；而在可测的稠密图上，
   静态拓扑量仍无区分度。** 结论是「放弃静态路线」，不是「放弃结构路线」。
4. 唯一通过检验的仍是边层（PAIR lift 1.454, z=4.10, p=4.1e-05）；NODE 两个判据全 NULL
   （未来判据 lift 0.794 p=0.128；结构判据 lift 1.045 p=0.655）。
   `machine learning` 这类**新实体**在 18% 采样下根本没被抽出来，是 NODE 路线的根本约束。

## 9. 评估修订（用户裁定）+ 树内 AUC：「方向反」的量化

### 9.1 用户的裁定

> 树太浅不是问题，评估要改。评估的有潜力方向要在树之内 —— 先了解树涵盖了哪些方向，
> 找到树中有潜力的方向作为测试集。

**采纳。** 这条修正直接修掉了 §8 暴露的一个真实缺陷：上一轮的阳性对照清单里
**7/12 个概念根本不在图内**（`machine learning`、`two-photon polymerization`、
`vat photopolymerization` …）。拿树外的对象判树内的排序器，等于让一次评估同时承担
两个职责（覆盖够不够 + 算法对不对），**两者混在一起会把「不可测」误判成「特征错」**。

**唯一必须守住的边界**：候选宇宙限制在树内 = 对；但「有没有潜力」这个标签
**不能也从树里推出来**，否则循环。标签必须来自树外的未来文献：

```
候选宇宙 / 特征  <-  树（<=2020 抽取）
标签             <-  未来文献（2021-2025 词面）      # 唯一不与特征同源的东西
```

### 9.2 树覆盖盘点（先回答「树里有什么」）

| 支撑度 | 概念数 | 可称为「方向」吗 |
|---|---|---|
| ≥1 | 7,359 | 绝大多数是长尾噪声 |
| ≥2 | 999 | 勉强 |
| **≥3** | **429** | **评估宇宙（与 P4-3 的伙伴宇宙一致）** |
| ≥5 | 171 | 比较像方向 |
| ≥10 | 54 | 成熟主题 |
| ≥20 | 20 | 大问题 |

**可打分（deg≥2）的只有 243 个**，另有 186 个够支撑度但度数不足 —— 它们能进评估宇宙，
但算不出结构特征。这是「树内测试集」的实际上限。

树内测试集规模（零重叠标签）：**243 个可标记，正例 75（30.9%）**。
`tools/evaluate_in_tree.py` 可一键复现并列出这 75 个方向。

### 9.3 为什么要换成 AUC

候选命中率（lift）把两个问题绑在一起：**候选池多大** + **池内排序对不对**。
AUC 只看排序，所以能先回答「算法有没有分辨力」，再单独回答「候选池该多大」。
本轮的 AUC 用 Mann-Whitney 正态近似，并且必须在三个标签窗口下都成立才算稳。

### 9.4 结果：不是「找到的没潜力」，是这个分数**与潜力负相关**

| 标签窗口 | 可标记 | 正例 | 复合分 AUC | p | 正例百分位中位 |
|---|---|---|---|---|---|
| 宽松（2011-2020 vs 2021-2025） | 243 | 80 | **0.424** | 0.053 | 0.442 |
| 严格零重叠（2016-2020 vs 2021-2025） | 243 | 75 | **0.451** | 0.218 | 0.453 |
| 严格更远（2016-2020 vs 2023-2025） | 243 | 80 | **0.434** | 0.096 | 0.442 |

**三个窗口全都 ≤ 0.5。** 也就是说：在树内，**真正在 2021-2025 扩张的方向，
被这个分数排在了后半段**（正例百分位中位 0.44）。

逐特征 AUC 把病因拆开了（三窗口一致，只列零重叠窗口）：

| 特征 | 权重 | AUC | p | 判定 |
|---|---|---|---|---|
| `structural_novelty` | 0.25 | **0.425 / 0.406 / 0.409** | 0.063 / **0.018** / **0.022** | **反向** |

### 9.5 这组数字同时证实和证伪了两件事

- **证实的**：`support`（规模）AUC ≈ 0.51–0.55，**零信息**。用户「潜力 ≠ 规模」的直觉是对的，

- **证伪的**：把 `growth` 也当成「规模」一起压到 0.05 是错的。

### 9.6 「方向反」到底是什么意思

不是「找到的没有潜力」。候选本身都是有意义的研究问题。精确说法是：

1. **这个分数与「潜力」在排序上负相关**（AUC 0.42–0.45 < 0.5，正例百分位中位 0.44）。
2. 分数高的是**已经连接很密的成熟节点** —— 它们**有价值，但未来不会突然爆发**。
   这正是用户上一轮的诊断（「找到的是大问题，不是新兴方向」），现在有了 AUC 量化。
3. 「结构位置能预测未来」这个问题**仍然没有被检验** —— 本轮检验的是一个**反向的**代理。
   不能读成「结构位置无用」，只能读成「这个操作化是反的」。
4. 好消息是：**尺子仍在树内可用**（243 个标记对象 vs 上一轮 12 个对照），
   特征筛选从「n=5 的对照」升级到「n=75/168 的 AUC」，功效问题解决了。

### 11.3 顺便修正上一轮一个错误归因：那个 0.666 是**标签几何**假象

上一轮说 `growth` 在 EVAL 上 AUC 0.67 是"跨测量体系"造成的。**归因错了。** 实测：

| 特征 | 标签窗口 | AUC |
|---|---|---|
| 词面增速 F（A 2011-14 → B 2015-17） | 内部相邻（B → C 2018-20） | **0.472** (p=0.31) |
| 同上 | 外部零重叠（2016-20 → 2021-25） | **0.547** (p=0.11) |
| 同上 | 外部**宽松**（2011-20 → 2021-25，10 年基线） | **0.666** |

**机制**：宽松标签用**10 年基线**做分母，而基线被早年低值拉低 →
任何在 TRAIN 内部上升过的概念**机械地**得到 `rate_ratio > 1`，**哪怕它之后完全走平**。
基线换成近 5 年，AUC 就从 0.666 掉到 0.547 不显著。
→ **`growth` 在 EVAL 上的"正向"是标签窗口几何的产物，不是预测力。**
（§9.4 的"宽松 0.699"同理。以后报 EVAL 结论应默认用零重叠窗口。）

### 11.4 内部门槛没有误判（补验证）

既然标签几何会骗人，也得反过来问：内部标签自己可信吗？

```

一致率 62.1%（L_int 正例 208 / L_ext 正例 142，427 个概念）
```

| **抽取族**（在 993 篇抽取计数上算） | 只有 **108 个概念**，每窗口计数中位 **1–3 次** | **不能** → 只能说"测不出" |

## 15. 边层事件型：已固化为工具（2026-09-13）

### 15.1 新增资产

| 文件 | 作用 |
|---|---|
| `tools/evaluate_edge_event.py` | 边层事件型评估器（默认 dry-run，`--apply` 落候选清单） |

| `tests/test_evaluate_edge_event.py` | 16 项回归测试 |

**为什么必须先固化**：过滤链原先以脚本 if 形式存在，无法复现也无法评审；
而 2026-09-12 一天内出现四次自造度量缺陷，全部是"判定规则没被固定下来"的后果。
本工具的测试守住：窗口不共享 / 过滤链逐条可测 / AUC 边界 / **各期各用自己的规模** / 输入来源解析。

### 15.2 固化中又抓到第五个坑：输入静默退回旧版本

工具首次运行给出 `n=261`、`adamic_adar` AUC **0.505** —— 与探针的 20,575 / 0.601 **差一个量级**。
原因：`--concepts` 默认走 discoverer 的 `CONCEPTS_PATH`（**旧的 993 篇 v1**），
而不是扩树后的 4,363 篇，**且没有任何报错**。

已修：
- 默认解析改为「扩树版存在则优先」
- 产物写入 `inputs.concepts_file` + `concepts_sha256` + `n_papers` + spec 的 `sha256`
- 端点 < 100 时打 `[WARN]`（"可能不是扩树版，结果不可比"）

**这是当天第五次"输入或口径错了却不报错"。共同教训：任何工具都必须把输入文件与哈希写进产物，
并对"输入规模异常"主动报警。**
