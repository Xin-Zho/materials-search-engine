## 3. API 预算

| 项 | 值 | 依据 |
|---|---|---|
| query 数 | 34 | cut 结果 |
| depth / query | **100**（首轮） | 用户建议 50–100 区间取上限；验证 yield 而非搜全 |
| Scopus API calls | ≤ 34×4 = **~136**（+20% retry margin → ≤170） | Search API 每请求 25 条，depth=100 需 4 翻页 |
| raw hits 上限 | 34×100 = 3400 | total_count<100 的实际更少 |
| 跨 query 去重后 unique | 估 1200–2200 | 同 A 不同 B 有重叠（如 C-01/C-02）；不同 A 词重叠低 |
| QA 单判量 | unique 全量 R/U/I | pc001 S6 QA 同量级（1365 条）已跑过 |
| LLM 熔断 | unique > 2500 截断 | 超预算按 action 顺序停，report 标注 coverage<1 |

> 成本假设：depth=100 下多数 thermo 窄查询 total_hits 在数十~数百（参考 pc001：17 query 中 13 条 <200）。若某 query total_hits 极大（如 MIT×switching）→ 仍只取 100，标 `depth_saturated=true`，**不加深**（首轮纪律）。

## 4. 停止条件（判定树）

```
对每个 action:
  Scopus total_count == 0  ──→ ZERO_HIT（登记 runs/pilot_zero_hits.json，不再翻页）
  Scopus 网络/配额错误     ──→ 分类 SOURCE_FAILURE / RATE_LIMIT（独立记录，不混入 ZERO_HIT）
  fetched == depth（饱和） ──→ depth_saturated=true（记录，Round 2 决定是否加深）

全局:
  unique_new 累积 > 2500   ──→ 剩余未跑 action 标 SKIPPED_BUDGET（不执行）
  34 全执行完              ──→ 正常收束（单轮硬停止）
  QA 单判仅对 unique 池     ──→ 无 abstract 论文标 NO_ABSTRACT（U 缓收语义沿用 R1）
```

## 6. Round 2 自适应规则（预冻结，B1 结果出来后按表决策，禁拍脑袋）

| Round1 观测 | Round2 动作 |
|---|---|
| family/域 (R+U) density 高（>0.4 估） | 启用该域半保留池 member 词 / 加深 depth→300 |
| density 中（0.2–0.4） | 同词族补第二个 B（如 leuco 补 coloration/decoloration temperature） |

| density 低且 total_hits 低 | 该机制词-thermochromism 关联弱 → 标记 deprioritize，不重跑 |
| ZERO_HIT / SOURCE_FAILURE | 不重跑（budget 纪律）；SOURCE_FAILURE 排除后重试一次同轮 |
