# v1.0 Literature Discovery Agent — Quickstart（一键运行说明）

- **配套**：`docs/2026-09-08-v1.0-release.md`（release note）｜ North Star spec（口径总纲）
- **环境**：`D:\materials-knowledge-base`，`.venv\Scripts\python.exe`（依赖见 `requirements.txt`）；OpenAlex 后端无需登录（可选 `OPENALEX_MAILTO` polite pool）；Scopus/LLM 路径需密钥（`DEEPSEEK_API_KEY` 等）
- **数据层纪律**：`data/` 不入 git，冻结产物以 `data/exports/releases/v1.0_manifest.json` sha256 锚定；一切写操作先 dry-run → 质量复核 → 分批 commit

---

## A. 最快复现：直接用已冻结产物（零 API 消耗）

冻结的 TermBank / seen set / QA labels / verdict / KB / R06 全在 `data/exports/`，read-only 复核入口：

```cmd
:: R06 三层 recall 复核（labels 已回填，可直接重算）
.venv\Scripts\python.exe tools\compute_r06_recall.py --labels data\exports\completeness_labels\pc_001__20260908012830_filled.json

:: 完整性校验（sha256 锚，检测任何版本漂移；git 跟踪文件锚 v1.0 tag blob，CRLF 无关）
.venv\Scripts\python.exe tools\verify_v1.0_manifest.py
```

产物地图（示例主题 pc_001）：
- TermBank：`data/exports/terminology/s6_term_bank.json`（40 VERIFIED_EXACT / 16 SEMANTIC）
- QA：`s6_qa_labels.json` / `s7_candidate_set.json`（R106/U22）
- 收录：`s8_finalkb_catalog.json`（249 篇）→ KB：`data/cache/knowledge_base.db`（216 records）
- 审计：`docs/2026-09-08-r06-recall-audit-report.md` + `data/exports/terminology/r06_recall_report.json`

## B. 端到端复跑 pc_001（完整链路，需 API）

按 freeze 顺序执行（各脚本自带 `--help`；dry-run 先行是硬纪律）：

```cmd
:: 0) 环境
set DEEPSEEK_API_KEY=...
set OPENALEX_MAILTO=you@example.com

:: 1) 检索 / Candidate DB（S5 冻结 base → S6 pilot）
.venv\Scripts\python.exe tools\run_search_s5.py --help
.venv\Scripts\python.exe tools\run_s6_pilot.py          :: S6 semantic bridge（17 actions，manifest 防篡改）

:: 2) QA（校准集 → RUBRIC_V1 → 全量盲评）
.venv\Scripts\python.exe tools\run_s6_qa.py --help

:: 3) Community discovery（簇 → verdict → KEEP 池）
.venv\Scripts\python.exe tools\build_s7_community_memory.py
.venv\Scripts\python.exe tools\build_s7_community_verdict.py
.venv\Scripts\python.exe tools\finalize_s7_candidate_set.py   :: 论文级 QA 终裁

:: 4) 主动探索 EX 组（reward 反馈驱动下一轮）
.venv\Scripts\python.exe tools\run_s7_execute.py --help
.venv\Scripts\python.exe tools\analyze_s7_reward.py

:: 5) S8 Promotion → KB 增量（dry-run → --commit）
.venv\Scripts\python.exe tools\run_s8_extraction.py --dry-run
.venv\Scripts\python.exe tools\run_s8_extraction.py --commit

:: 6) 独立 Audit（fresh sample → 外部盲评 → 三层统计）
.venv\Scripts\python.exe tools\build_r06_sample.py
.venv\Scripts\python.exe tools\label_completeness_sample.py --labels data\exports\completeness_labels\pc_001__20260908012830_filled.json
.venv\Scripts\python.exe tools\compute_r06_recall.py --labels data\exports\completeness_labels\pc_001__20260908012830_filled.json
```

> 注意：上面是 pc_001 已跑通路径的真实脚本序列。**复跑结果 ≠ 冻结版本**（freeze 后 query/QA 裁决已定，复跑仅验证可复现性；正式数字以 manifest 锚定文件为准）。

## C. 新主题 bootstrap（同一套 pipeline 换主题）

不要求主题必须是光固化——重建四样东西即可跑完整链路：

| # | 步骤 | 入口/工具 | 产出 |
|---|---|---|---|
| 1 | 定义研究问题 + relevance rubric（先于一切，禁事后补） | 手写 rubric 文档 | rubric（如 S6_QA_RUBRIC_V1 格式）|
| 2 | seed corpus：领域已知核心论文（几十篇量级） | `tools/re_extract_seed_papers.py` 等 | seed records（doi/EID/W 三通道）|
| 3 | TermBank：词源三层（lexical/mechanism/observable），VERIFIED_EXACT 门禁 | `tools/build_s6_qa_corpus.py` 系 | `*_term_bank.json` |
| 4 | Query/Relation Planner → 检索（Scopus/OpenAlex） | `python -m search_engine search "TITLE-ABS-KEY(...)"` / `tools/run_s6_pilot.py` | Candidate DB |
| 5 | Blind relevance QA（LLM + 人工校准） | `tools/run_s6_qa.py` | labels |
| 6 | Community discovery + verdict | 见 B-3 | KEEP 池 → 收录 |
| 7 | 独立 Audit（universe 构建 → fresh sample → 外部盲评） | 见 B-6 | 三层 recall 报告 |

通用入口兜底：`tools/run_autonomous_loop.py "研究问题" --rounds 3`（Phase 1.7 有界自主闭环：coverage → gap query → 搜索 → 筛 → 抽取 → 入库 → 重算），适合快速冒烟；正式多轮 discovery 走上面分阶段工具链。

## D. 纪律红线（v1.0 生效）

1. 词源纪律：正式 query 内容词只来自 VERIFIED TermBank + 冻结 context；SEMANTIC 仅 secondary 观测
2. Blind QA：AuditRelevant 判定必须独立（外部盲评），Search Agent 不能自证
3. 冻结裁决不可被重算覆盖；freeze 后文件改动使 sha256 失配即版本漂移
4. R06 口径：external-frame 13.9%/2.4%，禁表述为绝对召回率（见 release note §4）
5. 统计口径：resolved/ultra 双报；UNCERTAIN 归 R1 口径；Identity Unknown 不混入三层
